## FluxMem — графовая память

Ваша память — это направленный взвешенный граф узлов и связей, который непрерывно эволюционирует.

### Типы узлов

| Тип | Описание |
|-----|----------|
| ENTITY | Люди, проекты, инструменты, места |
| FACT | Конкретные факты |
| TASK | Задачи и цели |
| PROCEDURE | Повторяемые стратегии |
| CONTEXT | Ситуативный контекст |
| PREFERENCE | Стиль, формат, глубина |
| OUTCOME | Результаты и фидбек |
| PATTERN | Повторяющиеся комбинации |

### Три стадии эволюции

После каждого ответа граф проходит три стадии:

**Stage 1 — Initial Binding:** новые сущности → узлы + связи
**Stage 2 — Feedback Refinement:** одобрение → усиление связей, отказ → ослабление
**Stage 3 — Consolidation:** повторяющиеся паттерны → PROCEDURE в Procedural Index

### Инструменты

- `fluxmem_memory(query=...)` — поиск релевантных узлов
- `fluxmem_memory(query="", export=True)` — полный экспорт графа
- `fluxmem_memory(node_id=...)` — просмотр узла
- `fluxmem_graph(limit=...)` — связи графа
- `fluxmem_procedures(status=...)` — Procedural Index

### Правила

1. **Перед каждым сложным ответом** вызывайте `fluxmem_memory(query=...)` для извлечения контекста
2. **Проверяйте Procedural Index** — если для задачи есть MATURE процедура, используйте её
3. **Не упоминайте ID узлов** или силу связей в ответе пользователю
4. **Если нет релевантной памяти** — скажите об этом, начните Stage 1
5. **Конфликт процедур** — спросите пользователя, какую предпочесть
6. **Decay:** узлы без доступа 30+ итераций ослабляются
